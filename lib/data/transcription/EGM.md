# User-added transcription services

Non-secret configuration lives as JSON in settings.transcription_services: services (id/type/name/baseUrl/model/language/consentedFor) and a names archive for attribution after deletion. settings.transcription_engine is local or remote:<serviceId>. No schema migration is needed. LocalTranscriptionServices serializes mutations and key reads; engine reads wait for pending saves. Manifest writes precede secure writes, so every credential stays discoverable for delete/wipe even if key storage fails. Editing an active service temporarily deselects it; it is restored only after a successful save with valid consent. Changed type/URL invalidates consent; renaming, model edits and key rotation for the same destination retain it. Changed provider type or origin requires a new key. Key reads bound to a captured service reject a changed type/origin, preventing a stale job/form from sending a newly rotated credential to an old host.

ServiceKeyStore is the test seam. SecureServiceKeys uses flutter_secure_storage's default Android Keystore-backed implementation, keys fikra.transcription.api_key.<serviceId>. delete removes the key before the config; failure retains the manifest for retry. Wipe clears only this secure prefix and removes both settings rows including attribution aliases. Other secure-storage users are not cleared. A missing manifest requires no platform call, preserving ordinary offline settings behavior.

RemoteTranscriptionEngine implements the existing TranscriptionEngine interface and identifies results as remote:<serviceId>. It validates stored destination consent before opening audio or reading keys. No remote result, provider body, audio or key is printed or appended to experiment JSONL. All raw error details are discarded and mapped to stable reasons. Source aliases survive service deletion; aliases describe the service ID, not a historical model/version snapshot.

Request builders cite official docs next to their implementation. OpenAI-compatible uses multipart audio/transcriptions (file/model/optional language, JSON response). The current default gpt-transcribe uses languages[]; legacy gpt-4o-transcribe, gpt-4o-mini-transcribe and whisper-1 use language. Gemini generateContent uses inlineData and a verbatim-only prompt; documented M4A MIME is audio/m4a, raw AAC audio/aac. ElevenLabs uses multipart speech-to-text with xi-api-key, model_id, optional language_code and audio event tags/diarization off. Qwen compatible mode uses chat/completions with input_audio.data as a base64 Data URI, stream=false and asr_options. Singapore/Beijing legacy hosts are prefilled; workspace-specific current hosts are editable and recommended by Alibaba's docs. US compatible mode is not offered.

Original files stream for multipart; only inline APIs read the bounded file into memory for base64. Limits are checked before encoding: OpenAI 25 MB, Gemini 20 MB total JSON (including base64/prompt), Qwen 10 MB base64 input and ElevenLabs <5 GB. Normal saved clips are AAC-LC/M4A, <=5 minutes/~2.4 MB. Qwen also limits duration to 5 minutes; provider duration rejections map to tooLarge. Long trial WAVs can hit inline limits even when equivalent AAC fits. There is no chunking, Files API upload, asynchronous Qwen task API or remote live session in this phase.

HttpTranscriptionTransport uses dart:io HttpClient, connect timeout 15 seconds; total budget is 60 + ceil(30*MiB) seconds, capped at 600 seconds and shared across the format retry. It closes the client on timeout, bounds response bodies to 1 MiB, and refuses redirects. Only HTTPS is allowed except HTTP to localhost, literal loopback or RFC1918/IPv6 unique-local addresses. Arbitrary cleartext hostnames are rejected. TLS verification is unchanged. Native platform cleartext configuration is unnecessary for Dart-owned sockets; runtime URL validation enforces this policy.

A 415 or explicit 400 unsupported-format response may invoke the injected FFmpeg WAV fallback once; no proactive conversion occurs. Converted files are removed afterward. Errors: offline, keyRejected, rateLimited, tooLarge, serviceError, unexpectedResponse, remoteTimeout, consentRequired (plus the retained local reasons). No automatic network retry risks a second billed transcription.

Connection testing uses a bundled-as-code one-second 16 kHz mono PCM silence WAV (32,044 bytes), not user data. Any 2xx proves connection success even when silence yields no transcript. No live keys or network are used by tests.

Verification: dart format, flutter analyze; test/remote_transcription_test.dart, transcription_services_test.dart, transcription_engine_selection_test.dart and external_transcription_widgets_test.dart. The sandbox cannot run Flutter tests; API end-to-end, Keystore, TLS/LAN and provider account/model availability need the orchestrator/phone.

## Voice 2a: batch catalog and discovery

model_catalog.dart is the explicit capability allowlist, verified against the cited official docs on 2026-11-16. Entries record type/id/mode/label/status/shutdown/Arabic note/builder support. Only supported batch entries are selectable; Groq hosts offer the two Groq Whisper IDs. Gemini 3.5 Transcribe is shown as unsupported (/interactions is not implemented); native Qwen Audio 3.1 is omitted. Live defaults are null and no new live engine exists. OpenAI Diarize uses automatic chunking with the existing JSON text response.

TranscriptionService stores batchModel/liveModel, always accepts legacy JSON model as batchModel on read, and only writes the new shape. The model constructor/getter aliases preserve existing callers. Consent identity remains type + base URL, independent of model choice. Changing provider type drops the previous type's reserved live model in the form.

ModelDiscovery uses the existing fakeable HTTP transport for GET models (Bearer OpenAI-compatible, x-goog-api-key Gemini, xi-api-key ElevenLabs). Gemini follows pageToken/nextPageToken on the same base host. Responses only mark known catalog IDs as available; they never imply capability. Consent precedes even reading a key; discovery sends no audio. HTTP policy, redirect refusal and 15-second connection timeout are shared; discovery additionally caps the entire refresh at 60 seconds, 50 pages and 1 MiB. Failures discard provider/error text and keep selection and cache. Settings cache keys are transcription_models.<serviceId>.<URI-encoded-baseUrl>, with type, known IDs and checkedAt. Delete/wipe clears the cache. Qwen discovery is deliberately skipped because its native list protocol needs workspace context we do not derive.
