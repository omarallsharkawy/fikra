# فِكرة: الـAPI المطلوب من الباك إند

الملف ده لعلاء. مفيهوش أي تفاصيل Flutter. فيه اللي المستخدم بيعمله جوه التطبيق، والـendpoints اللي التطبيق هيكلمها.

التطبيق دلوقتي شغال demo من غير نت. الـendpoints دي هي اللي هنوصّلها لما الباك إند يجهز.

## الفكرة في 5 سطور

- النوتس والمشاريع والشات متخزنين على الموبايل، والتطبيق بيعرضهم من عنده.
- السيرفر بيشتغل على النص المكتوب بس: العنوان، المفاهيم، الروابط، إعادة الصياغة، والإجابة على الأسئلة.
- الصوت والـPDF والصور بيفضلوا على الموبايل. مفيش رفع ملفات، ومفيش parsing.
- السيرفر لازم يحتفظ بنص كل نوت (و embeddings بتاعتها) عشان يربط النوتس ببعض ويجاوب منها.
- التحليل بياخد وقت، فالتطبيق بيبعت النوت ويرجع يسأل على النتيجة كل شوية.

## الـendpoints كلها (8)

| # | Endpoint | بتتنادى إمتى |
|---|---|---|
| 1 | `POST /v1/devices` | أول مرة التطبيق يفتح |
| 2 | `POST /v1/notes/{note_id}/analyze` | بعد حفظ نوت، أو "جرّب التحليل تاني" |
| 3 | `GET /v1/jobs/{job_id}` | السؤال على نتيجة التحليل |
| 4 | `PATCH /v1/notes/{note_id}` | المستخدم عدّل النوت أو اعتمد اقتراح |
| 5 | `DELETE /v1/notes/{note_id}` | مسح نوت |
| 6 | `POST /v1/projects/{project_id}/ask` | سؤال في تاب "اسأل" |
| 7 | `DELETE /v1/projects/{project_id}` | مسح مشروع |
| 8 | `DELETE /v1/me/data` | "مسح كل البيانات" من الإعدادات |

## اليوزر ستوري جوه التطبيق

### 1. أول مرة يفتح التطبيق
المستخدم بيفتح التطبيق وبيعمل أول مشروع ويسميه. مفيش شاشة تسجيل دخول.

**السيرفر:** التطبيق بينادي `POST /v1/devices` مرة واحدة ويحفظ الـtoken. اسم المشروع مش بيتبعت. المشروع بيتعمل عندك لوحده أول ما توصلك أول نوت فيه.

### 2. يكتب نوت
المستخدم بيكتب عنوان (اختياري، لحد 80 حرف) ونص (لحد 5000 حرف) ويدوس حفظ. النوت بتظهر في الليستة فورًا وعليها "بتتحلل".

**السيرفر:** `analyze`، وبعدها `jobs` كل ثانيتين. لما النتيجة توصل، الكارت بيعرض العنوان والمفاهيم.

### 3. يسجل صوت
المستخدم بيسجل لحد 5 دقايق ويحفظ. الموبايل بيشغل التسجيل من عنده.

**السيرفر:** التسجيل مش بيتبعت، ومفيش تفريغ. لو كتب نص جنبه، التطبيق بيبعت النص بس بـ`analyze`. لو ماكتبش حاجة، مفيش أي نداء.

### 4. يرفق PDF أو صور
المستخدم بيختار PDF أو صور، وبتتحفظ مع النوت على الموبايل. لما يدوس عليها بتتفتح في تطبيق تاني على الموبايل.

**السيرفر:** الملفات مش بتتبعت. نفس قاعدة الصوت: النص المكتوب بس هو اللي بيوصلك.

### 5. نوت فيها ملفات ونص مع بعض
النوت الواحدة ممكن يبقى فيها PDF واحد، وتسجيل واحد، وصور، وجنبهم نص.

**السيرفر:** `analyze` و`jobs` على النص بس. لو النوت من غير نص، بتتحفظ جاهزة من غير تحليل، فمش هتظهر لها مفاهيم ولا روابط، ومش هتوصلك أصلًا.

### 6. يشوف النتيجة
لما التحليل يخلص، المستخدم بيشوف:
- **العنوان:** لو كان ساب العنوان فاضي بنحط اللي انت رجعته. لو كتب عنوان، عنوانه بيفضل.
- **المفاهيم:** tags على الكارت.
- **اقتراح إعادة صياغة** (لأي نوت فيها نص): زرارين "اعتمد" و"خلي الأصل".
- **النوتس المرتبطة:** في صفحة النوت، وكل واحدة جنبها سبب الربط (`label`).

### 7. التحليل فشل
النوت بتفضل محفوظة، وبيظهر "التحليل فشل" وزرار "جرّب التحليل تاني".

**السيرفر:** `analyze` تاني بـ`Idempotency-Key` جديد. النتيجة الجديدة بتستبدل القديمة. لو المحاولة القديمة لسه شغالة عندك، الغيها أو تجاهل نتيجتها. آخر محاولة بس هي اللي تتحفظ.

### 8. يقفل التطبيق والتحليل شغال
لما يفتح تاني، التطبيق بيكمّل لوحده.

**السيرفر:** التطبيق بيبعت `analyze` بنفس الـ`Idempotency-Key`. لازم ترجع نفس الـ`job_id` ومتبدأش شغل جديد.

### 9. يعدّل نوت
المستخدم بيعدّل النص، أو يعتمد اقتراح الصياغة، أو يرجّع الأصل.

**السيرفر:** `PATCH` فيها النص اللي بقى ظاهر، عشان "اسأل" يجاوب من آخر نسخة. التعديل مش بيعيد التحليل. لو رفض الاقتراح مفيش أي نداء.

المستخدم يقدر يعدّل والتحليل شغال. وقتها التطبيق بيستنى التحليل يخلص، وبعدها يبعت `PATCH`.

### 10. يفتح تاب الروابط
جراف فيه النوتس متجمعة في مجموعات، وخطوط بين المرتبطين.

**السيرفر:** مفيش نداء. الجراف بيترسم من `cluster` و`links` اللي رجعوا في نتيجة التحليل.

### 11. يسأل سؤال
المستخدم بيكتب سؤال (لحد 500 حرف) في تاب "اسأل"، وبيشوف "بيفكر"، وبعدها الإجابة وتحتها النوتس المصادر، وبيقدر يفتح أي مصدر.

**السيرفر:** `ask` جوه المشروع المفتوح بس. كل سؤال بيتبعت لوحده من غير تاريخ المحادثة. التطبيق بيستنى لحد 60 ثانية. لو مفيش إجابة في النوتس، بيظهر رد "ملقيناش" اللي انت رجعته.

### 12. يمسح
- مسح نوت: `DELETE /v1/notes/{note_id}`.
- مسح مشروع: `DELETE /v1/projects/{project_id}`.
- مسح كل البيانات من الإعدادات: `DELETE /v1/me/data`.

المسح لازم يشيل النص والـembeddings، ويشيل أي روابط للنوت دي. النوت الممسوحة ماينفعش تظهر تاني في إجابة.

أي id اتمسح (نوت أو مشروع، ومنهم اللي اتمسحوا بـ"مسح كل البيانات") مايترجعش تاني: لو `analyze` وصلتك متأخرة عليه رجّع `404`، وأي job شغال عليه يتلغي.

## قواعد عامة

- HTTPS بس، والـJSON بـUTF-8.
- كل طلب ما عدا `POST /v1/devices` فيه `Authorization: Bearer <token>`.
- كل الـids (نوت، مشروع) UUID v4 بتتعمل على الموبايل.
- **العزل:** كل بيانات المستخدم متربوطة بالـtoken بتاعه. لو id بتاع حد تاني جالك، رجّع `404`، ومتكتبش فوق بياناته.
- التطبيق بيبعت تعديلات النوت الواحدة بالترتيب.
- لو وصلك `PATCH` والتحليل لسه شغال عندك، التحليل مايكتبش فوق النص أو العنوان اللي في الـ`PATCH`.

شكل أي خطأ:

```json
{ "error": { "code": "bad_request", "message": "for logs only" } }
```

الـ`message` للّوج بس. التطبيق بيعرض رسايله هو.

| Status | معناه |
|---|---|
| `400` | الطلب ناقص أو غلط |
| `401` | الـtoken غلط |
| `404` | مش موجود، أو مش بتاع المستخدم ده |
| `429` | طلبات كتير |
| `5xx` | مشكلة في السيرفر، والتطبيق هيعيد المحاولة |

## تفاصيل كل endpoint

### 1. `POST /v1/devices`

بيعمل مستخدم جديد للجهاز. مفيش body.

```json
// 201
{ "token": "opaque-token" }
```

الـtoken من غير تاريخ انتهاء في النسخة الأولى. لو ضاع، بيانات المستخدم على السيرفر بتضيع معاه. حط rate limit على الـendpoint دي.

### 2. `POST /v1/notes/{note_id}/analyze`

Header: `Idempotency-Key: <UUID>`، جديد مع كل محاولة.

```json
{
  "project_id": "c0a8012e-1111-4a2b-8c3d-000000000001",
  "title": "",
  "text": "RAG بيجيب النص المناسب قبل ما الموديل يجاوب"
}
```

- `text` دايمًا فيه كلام. التطبيق مش بينادي `analyze` على نوت من غير نص.
- `title` ممكن يبقى فاضي.
- `text` هو النص اللي بتبحث وتجاوب منه. `proposed_text` مايتحسبش غير لما يوصلك `PATCH`.
- لو النوت موجودة عندك، البيانات دي بتستبدل القديمة.

```json
// 202
{ "job_id": "e3b0c442-98fc-4c14-9afb-f4c8996fb924", "status": "processing" }
```

### 3. `GET /v1/jobs/{job_id}`

التطبيق بينادي كل ثانيتين لحد ما `status` يبقى `ready` أو `failed`. خلّي الـjob ونتيجته 24 ساعة على الأقل. بعدها `GET` ترجع `404`، و`analyze` بنفس الـ`Idempotency-Key` تبدأ job جديد.

وهو شغال:

```json
{ "job_id": "e3b0c442-98fc-4c14-9afb-f4c8996fb924", "status": "processing" }
```

لما يخلص:

```json
{
  "job_id": "e3b0c442-98fc-4c14-9afb-f4c8996fb924",
  "status": "ready",
  "result": {
    "title": "إزاي RAG بيشتغل",
    "proposed_text": "RAG بيجيب الجزء المناسب من النص، وبعدها الموديل يجاوب بناءً عليه.",
    "concepts": ["RAG", "LLM"],
    "cluster": "الذكاء الاصطناعي",
    "links": [
      {
        "target_note_id": "aa11bb22-3333-4c4c-8d8d-000000000002",
        "label": "الاتنين عن RAG",
        "strength": 0.72
      }
    ]
  }
}
```

لو فشل:

```json
{
  "job_id": "e3b0c442-98fc-4c14-9afb-f4c8996fb924",
  "status": "failed",
  "error": { "code": "analysis_failed", "message": "for logs only" }
}
```

النتيجة بتغيّر النوت دي بس. متغيرش `cluster` أو روابط نوتس تانية، لأن التطبيق مش هيعرف بالتغيير.

معنى كل حقل في `result`:

| الحقل | القاعدة |
|---|---|
| `title` | دايمًا موجود، لحد 80 حرف |
| `proposed_text` | لو فيه تحسين فعلي. غير كده `null` |
| `concepts` | لحد 8، ومن غير علامة `\|` جوه أي مفهوم |
| `cluster` | اسم قصير للمجموعة. استخدم نفس الاسم لنفس الموضوع جوه المشروع، عشان النوتس تتجمع مع بعض |
| `links` | الروابط الخارجة من النوت دي بس، وبتستبدل روابطها القديمة. الأقوى الأول، والتطبيق بياخد أول 8. ممكن تبقى `[]` |
| `links[].target_note_id` | نوت تانية في نفس المشروع، مش النوت نفسها |
| `links[].label` | جملة قصيرة بتتعرض للمستخدم، لحد 80 حرف |
| `links[].strength` | من 0 لـ1 |

### 4. `PATCH /v1/notes/{note_id}`

```json
{ "title": "إزاي RAG بيشتغل", "text": "النص اللي ظاهر للمستخدم دلوقتي" }
```

`204`. الـ`text` ده بيستبدل نص النوت كله. حدّث الـembeddings، ومتشغّلش تحليل جديد.

لو النوت مش عندك رجّع `404`. ده بيحصل لو النوت اتحفظت من غير نص وبعدين المستخدم كتب فيها. وقتها التطبيق هيبعت `analyze` بالنص الجديد، عشان النوت تتحلل وتدخل في "اسأل".

### 5. `DELETE /v1/notes/{note_id}`

`204`، حتى لو النوت مش موجودة. لو فيه تحليل شغال عليها، الغيه، ومتخليهوش يرجّع النوت تاني.

### 6. `POST /v1/projects/{project_id}/ask`

```json
{ "question": "إيه اللي كتبته عن RAG؟" }
```

```json
// 200
{
  "text": "كتبت إن RAG بيجيب النص المناسب قبل ما الموديل يجاوب [1].",
  "source_note_ids": ["aa11bb22-3333-4c4c-8d8d-000000000002"],
  "found": true
}
```

لو مفيش إجابة في النوتس:

```json
// 200
{
  "text": "مفيش نوت في المشروع ده بتتكلم عن الموضوع.",
  "source_note_ids": [],
  "found": false
}
```

- الإجابة من نوتس المشروع ده بس.
- `[1]` معناها أول id في `source_note_ids`، و`[2]` التاني، وهكذا.
- لو المشروع لسه ماوصلكش فيه نوتس، رجّع `found: false` مش `404`.

### 7. `DELETE /v1/projects/{project_id}`

`204`، حتى لو المشروع مش موجود. بيمسح كل نوتس المشروع.

### 8. `DELETE /v1/me/data`

`204`. بيمسح كل نوتس ومشاريع المستخدم. الـtoken بيفضل شغال.

## مش محتاجينه في النسخة الأولى

- تسجيل دخول أو حسابات.
- `GET` لليستة النوتس أو المشاريع، أو sync بين الأجهزة.
- حفظ الشات على السيرفر.
- Streaming للإجابة، أو WebSocket، أو push notifications.

## محتاج منك يا علاء

1. الـbase URL بتاع الـstaging.
2. أطول وقت متوقع لتحليل نوت 5000 حرف. التطبيق حاليًا بيعتبر التحليل فشل بعد 90 ثانية، وهنظبطه على الرقم اللي تقوله.
3. لو عندك تعديل على أي endpoint، قولي قبل ما تبدأ عشان نتفق عليه.
